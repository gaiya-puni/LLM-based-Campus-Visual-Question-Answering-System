# 移动端测试手册

面向对象：本项目开发者、助教验收、以及负责线上部署的队长。
适用版本：`webapp/frontend` 移动端适配（2026-10-15）之后。

本手册提供**三套**互补的测试手段，全部可在本机独立完成，不依赖线上服务器：

| 手段 | 命令 | 覆盖什么 | 耗时 |
| --- | --- | --- | --- |
| 真机局域网联调 | `npm run dev:mobile` | 真机上的相机、定位、地图手势、触摸手感 | 一次性搭好后随开随用 |
| 多视口自动巡检 | `npm run test:mobile` | 8 种屏幕尺寸 × 全部页面与关键图表分支的横向溢出与裁切 | 约 1–3 分钟 |
| 人工验收清单 | 对照本手册第四节勾选 | 自动化难以覆盖的交互与系统级行为 | 约 10 分钟 |

线上站点（`https://ecnucampusvqa.cn/`）的部署由队长操作，因此另见第五节「给队长的部署后自检」。

## 一、真机局域网联调（`npm run dev:mobile`）

一条命令同时拉起后端与前端 dev server，并打印手机可直接打开的地址（装了 `qrcode-terminal` 时附带二维码）。

```powershell
cd webapp/frontend
npm run dev:mobile                       # 前端 + 后端（后端已在运行则自动复用）
npm run dev:mobile -- --no-backend        # 只起前端，后端你另开终端跑
npm run dev:mobile -- --port 5174         # 换端口
npm run dev:mobile -- --no-qr             # 不打二维码
```

启动成功后终端会给出：

```
前端已就绪，手机浏览器打开下面地址：
  http://192.168.x.x:5173/
  （本机自测：http://localhost:5173/）
```

### 为什么不用 80 端口

`vite.config.ts` 里 `server.port` 是 80，Windows 下绑定 80 需要管理员权限且易与 IIS 等服务冲突。联调脚本用 `--port 5173` 覆盖，**不修改 `vite.config.ts`**，桌面端 `npm run dev`（走 80）流程完全不受影响。

### 手机与后端如何通信

手机只需要能访问 Vite 的 dev server。页面里的 `/api` 请求由 Vite 在**服务端**代理到 `127.0.0.1:5000`，因此手机**不需要**直连 5000 端口，后端只要在这台开发机上跑着即可。

### 前提条件

1. 手机与电脑连同一个 Wi-Fi。
2. 首次运行若弹出 Windows 防火墙提示，勾选「专用网络」并允许访问；否则手机连不上。
3. `webapp/frontend/.env` 中 `VITE_APP_API_HOST` 指向本机后端（默认 `http://127.0.0.1:5000`）。缺这个文件时页面布局可看，但问答与热图接口会失败——脚本会给出警告。
4. 需要地图时确认 `.env` 里的高德密钥有效（见下方常见问题第 3 条）。

### 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 手机打不开地址 | 多数是防火墙拦截，或公司/校园 Wi-Fi 开启了「AP 隔离」（设备之间不能互访）。可改用手机热点让电脑连热点。 |
| 页面能开、地图空白 | 高德浏览器端密钥通常绑定了域名白名单，用局域网 IP 访问不被允许。属于预期现象，不影响布局与交互联调；需要验证地图时用 `localhost` 或线上站点。 |
| 提示端口被占用 | 用 `--port` 换一个端口。 |
| 后端未就绪 | 首次启动或数据库未配置时会较慢；也可另开终端 `cd webapp/backend; python server.py` 观察日志。 |

## 二、多视口自动巡检（`npm run test:mobile`）

在 8 种屏幕尺寸（手机 / 平板 / 桌面宽屏）下逐个打开全部路由页面，判定**页面横向溢出**与**宽图表被裁切**，并逐页截图归档。取代原先「手工 resize + 逐页截图」的验证方式。

```powershell
cd webapp/frontend
npm run test:mobile                  # 产物缺失时自动构建，然后巡检
npm run test:mobile -- --skip-build  # 复用已有构建产物
npm run test:mobile -- --only map    # 只看路由名/路径含 map 的页面
npm run test:mobile -- --headed      # 显示浏览器窗口（排查用）
```

> 注意：改过源码后请先删除 `webapp/frontend/build/` 再跑，否则复用的是旧产物。

### 覆盖范围

视口（含 768 断点临界、769–900px 的桌面骨架窄容器区，以及桌面宽屏零回归对照）：

`320×568`、`375×667`、`390×844`、`414×896`、`768×1024`、`800×600`、`1024×768`、`1440×900`

页面：直接读 `src/router/index.ts`，**新增路由会自动纳入巡检**，不必改脚本。

其中植物图表页会依次走到三个分支再判定（默认首屏看不到后两个，而它们正是最容易撑破页面的）：

| 分支 | 内容 |
| --- | --- |
| 植物类型 | 旭日图（按容器自适应） |
| 领养情况 | 桑基图（固定 900px 画布，容器内横向滑动） |
| 植物三维 | 平行坐标图（固定 900px 画布，容器内横向滑动） |

### 判定标准

一项检查通过，需要同时满足：

1. `document.documentElement.scrollWidth` 不超过视口宽度（允许 1px 取整误差）——即**页面没有横向滚动条**；
2. 不存在「宽图表被裁切」：`.chart-canvas` 的实际宽度超过其容器可视宽度，而容器又不可横向滚动。这类问题不会撑破页面（被 `el-card` 的 `overflow: hidden` 裁掉），但用户既看不全也滑不到，因此单独判定。

存在问题时会额外打印越界元素 / 容器尺寸线索；进程以非零退出码结束（`0` = 全通过），便于后续接入 CI。

### 结果与产物

- 控制台：逐视口、逐页面 / 分支的通过情况与问题明细；
- 截图：`webapp/frontend/tests/mobile-snapshots/<宽>x<高>/<页面>.png`；
- 报告：`webapp/frontend/tests/mobile-snapshots/report.json`（含每个检查项的 `scrollWidth`、容器尺寸、越界元素明细）。

该目录已被根 `.gitignore` 忽略（属本机测试产物）。需要作为报告佐证时再手动挑图入库。

### 浏览器来源：不下载任何浏览器

脚本复用**本机已安装**的 Edge / Chrome，按以下顺序探测：

1. 环境变量 `MOBILE_TEST_BROWSER`（直接给可执行文件绝对路径）；
2. Windows：`Program Files (x86)\Microsoft\Edge\...`、`Program Files\Microsoft\Edge\...`、Chrome 的两个安装位置；
3. macOS：`/Applications/Google Chrome.app/...`、`/Applications/Microsoft Edge.app/...`；
4. Linux：`/usr/bin/google-chrome`、`/usr/bin/microsoft-edge`、`/usr/bin/chromium`。

依赖只有 `playwright-core`（仅驱动、体积几 MB），**不会**下载约 150MB 的专用浏览器构建。若要用别的浏览器：

```powershell
$env:MOBILE_TEST_BROWSER = "D:\other\chrome.exe"
npm run test:mobile
```

## 三、人工验收清单

自动化解决不了的项（真机手感、系统权限、原生行为）请对照勾选。建议在 `npm run dev:mobile` 的真机上执行。

### 系统与权限

- [ ] 相机：问答页 / 识花弹窗点上传，能调起**后置**相机（输入框带 `capture="environment"`）。
- [ ] 定位：允许授权后地图能定位到校园位置；拒绝授权时有可读提示、页面不崩溃。
- [ ] 显示：刘海屏机型顶部内容不被状态栏遮挡（`env(safe-area-inset-top)` 生效），底部标签栏不被手势条压住。
- [ ] 横竖屏切换后，地图与图表能重新铺满（不再出现只有一半的情况）。
- [ ] 输入框聚焦时页面**不会**被放大（输入字号 ≥16px），键盘弹起后按钮仍可点到。

### 导航与布局

- [ ] 底部标签导航四项（主页 / 地图 / 问答 / 寄语）可点击、选中态正确。
- [ ] 「更多」底部抽屉能打开，三个入口（植物图表 / 数据审核 / 热力图生成）都能跳转。
- [ ] 逐页左右拖动，页面本身**不出现**横向滚动。
- [ ] 问答页在「对话 / 地图」之间切换：两个视图都铺满、切换不残留白块；回答带出地图标注时自动切到地图视图。
- [ ] 地图页筛选按钮换行后仍可点，植物库模式表格可横向滚动查看。

### 弹层与组件（本轮修复重点）

- [ ] 数据审核页点开某一行 → 详情抽屉**完整落在屏幕内**（铺满宽度）、按钮与输入框够大、可内部滚动。
- [ ] 热力图生成页的候选地点抽屉同样铺满屏幕、不越界。
- [ ] 留言板（寄语页点某行）弹窗宽度贴近屏幕，卡片不被裁切。
- [ ] 预测页弹窗宽度正常（不再按 50% 窄条显示）。
- [ ] 问答回答下方的「有用 / 没用」按钮触控面积够大（≥44×44），已评价时能看到「再点一次可撤回」的**可见提示**（不再只靠长按 / 悬停）。
- [ ] 植物图表页三个分支都能左右滑动查看完整图形，且滑动时提示文案可见。

### PWA（iOS）

- [ ] Safari 打开线上站点 → 分享 →「添加到主屏幕」，图标与名称正确、打开后全屏（无地址栏）。
- [ ] 主屏幕打开后能正常问答（`/api` 建议保持在线，离线时至少页面框架可用）。

## 四、给队长的部署后自检（约 5 分钟）

线上部署由队长执行，本地测试通过不代表线上可用，部署后请按此清单确认。

1. **站点可达**：手机浏览器打开 `https://ecnucampusvqa.cn/`，首页正常渲染、无横向滚动条。
2. **接口在线**：随便问一个问题（如「食堂在哪」），能返回文字答案与地图打点；失败时先查后端进程与 `/api` 反向代理配置。
3. **地图正常**：地图页能看到校园底图与标注。若空白，通常是高德密钥的域名白名单未包含正式域名。
4. **PWA 清单与图标**：访问 `https://ecnucampusvqa.cn/manifest.webmanifest` 能正常返回，`/icons/pwa-192.png`、`/icons/pwa-512.png` 可访问。
5. **Service Worker**：手机 Chrome 打开 → DevTools → Application → Service Workers，应看到 `sw.js` 已激活；确认 `/api/` 请求**没有**被 SW 缓存（保证问答实时性）。
6. **缓存版本**：本次只改了前端业务代码时，SW 会自动更新；若改动了 `webapp/frontend/public/sw.js` 的缓存策略，请同步修改文件顶部的缓存版本号，避免老用户命中旧缓存。
7. **首次引导**：PWA 上线后用户需要**手动**「添加到主屏幕」一次才会全屏独立运行，页面内可提示这一点。
8. **安卓 APK**：若需要出包，用 HBuilderX 导入 `mobile-app/` → 发行 → 原生 App-云打包（步骤见 `mobile-app/README.md`）。业务改动只需重新部署 H5，**不必重打 APK**。

## 五、出问题时的排查顺序

1. **先看是不是产物没更新**：删掉 `webapp/frontend/build/` 重新构建；巡检脚本已禁用浏览器 HTTP 缓存，但手工用浏览器验证时请硬刷新（Ctrl+Shift+R）或关闭标签页重开。
2. **再看是不是页面状态残留**：本项目是 hash 路由，只改 URL 的 hash 不会整页重载，上一页打开的抽屉 / 弹窗会留在页面上并拦截点击。手工验证时请在 URL 上带一个变化的查询参数（如 `/?r=9#/map`）强制整页加载。巡检脚本已自动处理这一点。
3. **量一下尺寸**：在浏览器控制台执行
   ```js
   document.documentElement.scrollWidth - window.innerWidth   // > 0 说明页面横向溢出
   ```
   再用 `document.querySelectorAll('body *')` 过滤 `getBoundingClientRect().right > innerWidth` 定位具体元素。
4. **怀疑样式没生效**：Element Plus 的 `el-dialog` 会 teleport 到 `body`，渲染后的 `body > .el-overlay > .el-dialog` 链路上**没有任何元素带组件 scopeId**，所以组件里写 `.el-dialog { … }` 和 `:deep(.el-dialog) { … }`（编译成 `[data-v-xxx] .el-dialog`）**都命中不了**——弹窗尺寸规则必须写在全局 `src/style.css` 里（`views/message.vue` / `views/predict.vue` 曾因使用 `:deep` 而"改了没生效"，2026-10-16 已修）。`el-drawer` 的宽度走 `size` prop，不受此限制。排查时可在控制台直接确认：`document.querySelector('.el-dialog').getAttributeNames()` 里有没有 `data-v-*`。
5. **怀疑容器尺寸变化后页面没重排**：地图用 `ResizeObserver` 触发 `map.resize()`，图表由 `components/Echarts.vue` 的 `ResizeObserver` 自动 `resize()`，两者都只在容器上监听并在卸载时断开。
